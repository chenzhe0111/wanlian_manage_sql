# 万联线上订单 · 数据分析

## 何时用本 skill

- 解读或刷新：**新老漏斗**、**线上占比**、**四举措归因**
- 输入多为：`03c/03d` 导出 CSV、桌面周报 Excel、飞书进度文档表3
- **不要**与「只更新本周进展/下周计划」混写；进展/计划走 `weekly-progress-plan-summary` 规则

## 命名映射（必须统一）

| 业务名（表/话术） | 数据字段（SQL/CSV） |
|---|---|
| 裂变营销 / 货主招募 | `货主招募` |
| 电销挖潜 / 资源转化 | `电销` |
| 端外 / 投流 | `投流` |
| 资源合作 / 调度 | `调度`（表内常拆 撮合 / TMS / 网货） |

周标签：`M{月}W{周}`，周起始=**周三**。例：`2026-08-26` → M8W5；下一周 `0902` → M9W1。

## 核心口径（写结论前先确认）

1. **履约剔异常**：成交轴=`unload_time`；`load/unload` 均非空；排除异常剔除+申诉中（同 `01c`/`03*`）。
2. **新老货主**
   - **月度**：`first_dt >= 当月月初`（月内首活=新增）→ `03c` / `03d` 月度一致
   - **周度（新）**：`first_dt >= 当周 week_start`（当周首活=新增）→ **`03d`**
   - **周度（旧）**：周也按月月初判新 → **`03c`**
3. **混口径警告**：只刷某一周（如仅 M8W5）到新口径时，对照周若仍为旧口径，环比须注明「仅供参考 / 待同口径刷新」。
4. **调度表3**：明细行多为撮合·TMS·网货（类型），不是留存/新增；新老结论可写在分析列，**勿擅自改类型行业务数**（除非用户明确要刷）。
5. **详单行数 ≠ 多周 SUM**：周度是每周 `COUNT DISTINCT`；跨周加总会重复计数货主。

常用 SQL：

- 周按周首活漏斗：`manage/03d_月度周度新老漏斗_周按周首次_履约剔异常.sql`
- 周按月判新（旧）：`manage/03c_月度周度新老漏斗_认证注册发货成交_履约剔异常.sql`

## 数字格式

- 人数 / 货主数：**取整**
- 转化率、完成度、周环比：**百分位**（`+12%` / `-3pp`）
- 运单：**万单，约 3 位小数**（`1.033`）
- 单货主运单数 / 人效：**不是 %**
- 完成度 vs 时间进度：超前/落后写 **pp**；飞书表色约定以当前文档为准（常见：红≈达进度、绿≈落后）

## 三类分析模板

### A. 新老漏斗（留存 / 新增）

按举措输出（裂变/电销/投流；调度有新老数则单写一段）：

1. **合计运单**：当周量 + 周环比（量与 %）
2. **结构**：留存 vs 新增量级、占比；谁托底、谁拖累
3. **新增漏斗卡点**（有数才写）：注册→认证→发货→成交；点明最弱一环
4. **口径一句**：用的是 03c 还是 03d

结论忌堆全漏斗原文；**3～5 句**。

### B. 线上占比

1. **水位**：线上运单、线上占比、环比/同比（pp）
2. **联动**：量升/降是否带动占比，或被线下/大盘稀释
3. **贡献**：四举措谁抬占比、谁拖占比（可用简易归因：Δ线上 ≈ 各举措Δ之和，余项归大盘/其他）
4. **一句话总判**

矩阵月表（4→N 月）另遵 `platform-matrix-h2-targets` 五段结构。

### C. 四举措归因

1. **整体**：当周/当月总量路径 + 环比
2. **分举措**：各写量级、增速、占比变化；标明托底 / 加速 / 仍弱
3. **结构**：是否「单极」→「主+跟进」
4. **新老或类型**（按问题选一侧，不要两套并行堆砌）
   - 裂变/电销/投流 → 优先新老
   - 调度 → 优先撮合·TMS·网货
5. **一句话总判**

### D. 进度慢 / 谁拖累（针对性，忌速览堆砌）

问「进度为什么慢 / 谁拖累」时，**先点名再下钻**，不要铺全表：

1. **拖累举措**：四举措按「达成率 − 时间进度」排序；点名最差 1 个 + 其次；点名托底
2. **举措内运单类型**：用周度 CSV（`线上举措-{裂变货主招募|电销|投流|调度}-{TMS|撮合|网货}`）看近两周变动；掉量最大的类型=举措内拖累
3. **特例**：主拖累月量≈0（如裂变）时，类型下钻改看「有量的次差举措」（常见投流）
4. **一句话**：举措名 + 类型名 + 整体落后时间进度 pp
5. 线上专项问法：可再补线上-TMS/撮合/网货月达成（整合表 86–88 行）

实现：`scripts/quickbi_export/qa_analyze.py` → `answer_why_low`

### E. 四举措新客贡献是否提升

问「新客户贡献有没有提升 / 新增怎么样」时：

1. **数据源**：整合表「七、线上举措转化」实际列（9月=M … 12月=P），与 `refresh_sheet_actuals` 同本
   - 裂变：新增 row103 / 留存 row107
   - 电销：新增 row120 / 留存 row113
   - 投流：新增 row149 / 留存 row142
   - 调度：新增 row169 / 留存 row170
2. **对比窗口**：上月整月 vs 本月截至 O1；**禁止**用未完月累计直接比整月绝对量
3. **必算两套指标**
   - **新增日均（月口径）** = 新增月量 ÷ 统计天数（上月自然日；本月=O1 日）。**不是周度日均**；与「近周类型」周 CSV 分列标注
   - **新客占本举措比重** = 新增 ÷ (新增+留存)
4. **总判口径**：日均升且比重升→贡献提升；日均降或比重掉→未提升/下滑；点名谁掉最狠、谁托底
5. **一句话**：先答「有/没有提升」，再点 1～2 个关键举措

## 写入飞书「3、线上订单进展」时

- **默认只动**：周度列（用户指定的周）、周环比、分析结论；月目标/月实际/同比/完成度未点名则不动
- **本周进展 / 下周计划**：有材料才压成编号 3～4 条动作清单；无材料标「待业务确认」；**禁止**把漏斗复盘写进进展
- 分析结论模板骨架：
  1. 周度量级 + 环比（注明周标签与口径）
  2. vs 时间进度 + 同比/完成度
  3. 留存·新增或撮合·TMS·网货拆解
  4. （可选）周报观察一句
- 改完用 `lark-cli docs +fetch --as user` 回读抽查关键数

## 输出风格

- 先给 **1～2 句总判**，再分点
- 关键数加粗宜少；优先「谁在动、卡在哪、下一步盯什么」
- 数据缺口明确写「待业务确认 / 待同口径刷新」，不要编数

## 反例

- ❌ 只更新 M8W5 却把表头改成 M8W4|M8W5、丢掉 M9W1
- ❌ 把完成度、周环比长段塞进「本周进展」
- ❌ 用多周新增货主数相加对比详单去重人数
- ❌ 调度类型行当新老行改数
